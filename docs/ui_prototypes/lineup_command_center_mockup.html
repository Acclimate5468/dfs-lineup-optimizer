Porting this into Streamlit

This mockup is a view layer only. Every signal shown maps to a value the app already computes in evaluate_manual_review(conn, slate_id) (the Phase C read aggregator in src/slate/manual_review_service.py). Porting = rendering that existing ReviewReadiness result with this layout. No new business logic, no schema change, no extra DB writes.

1. Data already exists — reuse it

  • readiness = evaluate_manual_review(conn, active_slate_id) → read-only, one call per render.
  • Index readiness.checks by .code; each card reads that check's .status (pass/warn/block) and .message.
  • Gauge counts come straight from readiness.summary (blocking_count, warning_count, info_count, ready).
  • Optimizer / Export cards read the same readiness.summary.ready gate the two pages already enforce — they report availability, not completion.
  • Fighter-count / fight-count chips are cheap len() reads (or widen ReviewReadiness to carry them, per HOME_DASHBOARD_UX_DESIGN §9).

2. The "next action" is a pure mapping

Implement recommend_next_action(readiness) -> NextAction as a pure, unit-tested function (proposed src/slate/home_dashboard.py) using the precedence in HOME_DASHBOARD_UX_DESIGN §5: no slate → Slate Setup; gate_ready → Optimizer; structurally-clean-but-unacked → Manual Review; otherwise the first failing Blocking check maps to its page. The hero panel renders its label/why/target only.

3. Component mapping (mockup → Streamlit)

  • Top bar slate picker → single st.selectbox writing st.session_state["active_slate_id"] (the global-slate idea in §6).
  • Status cards → st.container(border=True) + st.metric + a colored status chip; the 3-col grid → st.columns(3).
  • Pipeline stepper → a row of small st.columns with an icon per step (pure markdown/HTML via st.markdown).
  • Checklist rows → the 9 workflow rows; link with st.page_link("pages/NN_*.py", …) (deferred to A5.4 behind an AppTest-compat check; plain text fallback first).
  • Color system → a small CSS block injected once via st.markdown(unsafe_allow_html=True), or Streamlit-native st.success/st.warning/st.error if you want zero custom CSS.

4. Hard constraints carried over

  • Read-only on load (docs/DEVELOPMENT_NOTES.md §11): page load + slate switch are reads only. No INSERT/UPDATE/DELETE.
  • No optimizer run / no export build on load — the cards display the gate state; they never call run_optimizer or build_run_log.
  • No re-deriving verdicts — render ReviewCheckResult.status; don't re-classify checks (avoids drift from the Manual Review gate).
  • No effective_status promotion — consume only what the aggregator already surfaces.

5. Suggested slice order

A5.2 home dashboard (cards + checklist + next-action, plain-text links, active_slate_id written home-only) → A5.3 per-page slate opt-in → A5.4 st.page_link deep-links + copy polish. Each ships with the AppTest + pure-function unit tests listed in HOME_DASHBOARD_UX_DESIGN §8.
